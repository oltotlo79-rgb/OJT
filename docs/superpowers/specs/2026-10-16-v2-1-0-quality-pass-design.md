## 2. 設計

### 2.1 ビューキューブと視野（U1・U4・U10・U11）

- **視野角を 38° → 24° にする**（`three/camera.ts` の `CAMERA_FOV_DEG`）。同じ枠に盤を収める距離が約1.6倍になり、高さ約56mmのリレーが画面の外側へずれる量（視差）が約4割減る（`fov/fov38-*` と `fov/fov24-*` の比較で CR1 が盤の左縁から出なくなる）。寄れる距離・離れられる距離は、見える幅が以前と同じになるよう換算する（下限 90 → 145mm、上限 1200 → 1900mm）。E2E の射影（`projection.ts`）・3Dの単体テストは同じ定数を読むので追随する。
- **カメラの合わせ方にビューキューブの場所を入れる**。`cameraPose(preset, { aspect, viewportPx })` に画面の大きさ[px]を渡すと、`gizmoLayoutForViewport()` が決めるキューブの下地の正方形（角から `2 × margin`）を避けて中身を収める。避け方は「横にずらす（使える幅 = 幅 − 2m）」と「縦にずらす（使える高さ = 高さ − 2m）」の2通りを計算し、中身が大きく映るほうを選ぶ。カメラの向きは変えず、注視点と位置を同じだけ平行にずらす。キューブが出ない幅（600px 未満など）では何もしない。
- 対象のプリセット: 正面・背面・左右・下・ソケット拡大・PLC。**「上から」（2）は固定の斜め位置をやめ**、同じ向きのまま盤の箱（ソケット・リレーの高さを含む）の8隅が枠に収まる距離を二分探索で求め、そのうえでキューブを避ける。
- **キューブの置き場所はどの画面でも左上**にそろえる（PLC の視点だけ右下だった）。左上には状態の表示があるので、キューブはその下（既定の余白）に置く。
- 検査: 単体テストで、5つの窓の大きさ（1264×761・1424×861・1904×1041 の盤ペイン、PLC分割の 640×320、並べての 900×300）× 各プリセットについて、中身の箱の8隅を射影した外接矩形がキューブの下地の正方形と交わらないことを確かめる。

### 2.3 3Dの名札（U3）

- **銘板（PLC本体の型式「FX5U-32MR/ES」、ラックのモジュール形式「IN-12」「OUT-12」「POWER1」「JW-301PU」など、ラックのベースの「PC10G-1SP」「JW-300」）を HTML の名札ではなく本体の面に描く**（Canvas テクスチャの板。端子の印字と同じ作り方）。3Dと一緒に縮むので、表示灯・端子に重ならない。
- 機種名（「三菱 MELSEC iQ-F FX5U-32MR/ES」）・壁コンセント・固定機器（ブレーカ・電源スイッチ・DC24V電源）の名札は残し、**名札の端を機器の外側に揃える**（下に出す名札は上端、上に出す名札は下端を基準点に合わせる。drei の `Html center` をやめて transform で揃える）。名札の大きさがどうであれ、機器の側へははみ出さない。

### 2.6 小さな UI の直し（U7・U8・U9）

- **C2 の指摘の小窓**: 押した点（`popoverAnchor`）の近くに出す。小窓の高さは見積もり（380px）ではなく、開いたあとの実寸で上下を決め、3Dペインの下端（押ボタンの帯）にはかからないようにする。小窓が出ている間は端子の札（ホバー）を出さない。見出しの呼び方を札と同じ「S1 端子9（CR1⑨）」の形にそろえる。

### 2.7 PLCの表示灯と運転状態（P2・P3）

- Worker のスナップショットに **`plcIo`（電源の可否・入力・出力）を常に載せる**（モニタ中だけ載せていた `plc` はそのまま）。3D の表示灯は次の規則にする:
  - POWER／PWR: PLC の電源（壁コンセントの L・N から正しく給電）が来ているときだけ点灯。
  - RUN／P.RUN: 給電中かつ RUN のとき点灯。
  - ERR／ERR/ALM: 給電中で、書き込んだプログラムが無い状態で RUN した、または変換エラーのとき点灯。
  - 入力・出力の表示灯: 給電中なら**モニタの有無にかかわらず**実際の入力・出力を映す。給電されていなければ全部消灯。
- 手順帯の「PLC:」の札は、給電されていなければ「PLC: 電源なし」と出す（運転の指示は覚えたまま。給電されれば RUN に戻る）。

### 2.8 PLCへの書込み（P1）

- **PLC は書き込まれたプログラムで動く**。ストアに「PLC のプログラム」（書込みのときのラダーの写し）を持ち、Worker へ送るのは書込みのときだけにする。変換は格子の誤りを調べて実行形式を作るだけで、動作は変えない（実機と同じ）。
- 書込みの操作: 三菱「シーケンサへの書込み」、オムロン「転送［PC → PLC］」、シャープ「PLCへの書込み」、ジェイテクト「**PCへ書込み**」（道具列に足す。PCwin の資料が未入手なので、名前は前提として設定の「この見た目の根拠」に残す）。変換が要るメーカーで未変換なら、いまどおり「先に変換（F4）してください」。
- RUN 中に書き込もうとすると「運転中（RUN）のPLCには書き込めません。STOPにして書き込みますか？」と確かめ、「STOPして書き込む」で STOP → 書込み。書き込んだあとは STOP のまま「書き込みました。RUN にすると新しいプログラムで動きます」と知らせる。
- プログラムが無いまま RUN: 「PLCにプログラムがありません。書込みをしてから RUN します」と断る（ERR 表示灯が点く）。
- 手順帯: ①配線（3D盤）②ラダー作成 ③変換（無いメーカーは出さない）④**書込み** ⑤モニタ開始・RUN ⑥判定。書込みの「済」は「PLCのプログラムがいまの変換結果と同じ」。手順帯の札に「PLCのプログラム: 書込み済み／エディタと違う（書込みが必要）／なし」を出す。
- 判定: PLC に書き込まれたプログラムで判定する（実機の試験と同じく「動いている PLC」を見る）。エディタに書き込んでいない変更があるときは、判定の前に「エディタの変更がPLCに書き込まれていません」と確かめ、「書き込んでから判定」「このまま判定」「取消」を選べる。
- PLC実験の「動かす」も書き込まれたプログラムで動かす（無ければ「書込みをしてから動かします」）。
- 作業ファイル・自動保存: PLC のプログラムも保存し、読み込むと PLC はそのプログラムを持ったまま STOP で始まる（実機の PLC が電源を切ってもプログラムを覚えているのと同じ）。**以前の作業ファイル**（PLC のプログラムが無い）は、変換済みならその回路を書込み済みとして扱う（以前と同じ動きのまま開ける）。
- メーカーの切替（表記切替・機種の切替）は机上の PLC 本体が替わるので、PLC のプログラムは空になる（書き直しが要る）。切替の窓の注意文にそのことを足す。

## 3. 互換性

- 作業ファイル: PLC のプログラムが無い以前のファイルは、変換済みならその回路を書込み済みとして開く（動きは以前と同じ）。新しい項目（PLC のプログラム、名札の表示）は省略可。
- 課題 JSON・判定基準は変えない（判定に使うラダーが「書き込まれたもの」になるだけ。内蔵課題の自己判定は模範ラダーを直接使うので影響しない）。
- 視野角が変わるので、以前の版で撮った説明書の図・動画とは見え方が少し違う（すべて撮り直す）。
