## 3. 設計

### 3.1 説明書と実画面の通し点検（R1）

- 15章すべてを**実画面の自動操作**で通し、章・節ごとに「説明書の記述 → 実画面の状態 → 一致／不一致 → 対処」を `OJT/release/verification/v2.0.0/manual-walkthrough.md` に残す。撮影は既存の `manual-shots.spec.ts` の手順を流用し、拡大図も含める。
- 不一致は「画面を直す」か「説明書を直す」かを1件ずつ決める。画面の文言は `i18n/ja.ts` だけを直し、説明書は `docs/manual/*.md` を直す（生成物 `help/manual-content.ts` は `build-manual` で再生成）。
- 既存の機械検査（`manual-sync` / `manual-coverage` / `feature-inventory`）はそのまま門として使う。

### 3.2 手順帯の「部品装着」（F1）

- 「部品装着 済」= **課題の模範回路で使う役割の部品（CR1・T1 など）が全部そのソケットに載ったとき**。在庫の残りは見ない。
  - `packages/content` に `requiredPartRoles(problem)`（模範回路図・模範ラダー・PLCのI/O割付が参照する CR/T の役割の集合。部品点検・実験は空）を足す。
  - `assembleSteps()` の入力を `partsRemaining`（在庫）から `requiredRoles` / `mountedRoles` に替える。1個も要らない課題（役割が空）は最初から「済」。
- 案内の1行は「CR1 をソケット S1 に載せます（残り: T1）」のように**次に載せる役割とソケット**を言う。全部載ったら配線の案内へ進む。
- 在庫の表示（「残り 1」）は変えない。「未使用部品」の静的チェックも変えない。
- 単体テスト: 必要な役割が空／一部／全部のときの `state`、PLC・実験の帯が変わらないこと。実画面: b-001 で CR1 を載せた直後に「部品装着 済」になること。

### 3.3 PLCの「分割」表示（F2）

- 分割では**3D盤の欄に最低 300px の高さ**を確保し、幅は欄の高さ×縦横比（2.0）で決める。左列の課題・部品欄はその下でスクロールする。1280×800 でも 3D盤が 560×280px 以上になるよう `--plc-board-w` の下限を 560px にする。
- ラダー編集面は残りの幅をすべて使う（1280px では `minmax(0, 1fr)` のまま）。
- 検査: `ui-quality.spec.ts` の分割表示（4メーカー×3解像度）で、3D盤の実寸と札の重なり0件（`label-declutter` の集計）を見る。

### 3.4 ソケット・部品の選択表示（F3）

- 選択中のソケットは**本体を光らせず**、台座の輪郭（`EdgesGeometry`）を水色・太線で描く。ホバーは白の細線、落とせるソケットだけ弱い発光（0.35）を残す。
- 装着部品の稜線の色（`mountedEdgeColor`）はそのまま。透明なリレーのケース越しに台座が水色に染まることが無くなる。
- Phase 7 設計 §7.3.4「ホバー＝細い縁取り、選択＝太い縁取り」の本来の形に戻すだけなので、E2E の `socket-card` / 装着の検査は変えない。

### 3.5 3Dの品質（R3）

**描画の土台**
- `Canvas` に ACES トーンマッピング（露出 1.0）と `RoomEnvironment` から作る PMREM 環境マップ（外部ファイルなし・オフライン）を足し、金属・樹脂に映り込みを与える。影は PCF のまま、`shadow-mapSize` を 2048 に上げる。`frameloop="demand"` と描画予算（`PerfProbe`）は変えない。
- 材質を実物に寄せる（`materials.ts` に名前付きの材質を集める）: 盤面＝半艶の塗装（roughness 0.6）、DINレール＝亜鉛めっき鋼（metalness 0.85 / roughness 0.35）、ネジ＝ニッケルめっき（metalness 0.9）、ソケット・端子台＝黒いPBT（roughness 0.5）、電線＝PVC（roughness 0.45、青・白・黄）、圧着端子＝黄銅（metalness 0.8）＋**絶縁スリーブ（赤。1.25sq用）**、リレーのケース＝透明ポリカーボネート（反射あり、opacity 0.3）、タイマ＝黒い筐体。

**形の作り込み（寸法・位置は変えず、見た目だけ）**
- ネジ端子: 頭の十字溝（既存）に座金（ワッシャ）と角座を足す。圧着端子はY型の板に**赤い絶縁スリーブ**を付け、電線はスリーブの中へ入る（接続が目で分かる）。
- 端子台（ランプ用・押ボタン用）: 段付きの台座に仕切り、両端の固定ねじ、銘板。ランプ: クロームの化粧リング＋ドーム型レンズ（点灯時は内側から光る）。押ボタン: 化粧リング＋ガード＋押し込むヘッド（既存のアニメーションは維持）。
- ブレーカ（2P 1A）: ハンドルの窓に ON/OFF の印字、定格ラベル、端子カバー。電源スイッチ: ロッカーの I/O（既存）＋照光の縁。DC24V電源: 端子台のP/N印字（既存）に端子カバーとLED。
- リレー MY4N: 透明ケース、内部（コイル・鉄心・接点ばね。既存）に**橙色の動作表示LED窓**と機械式インジケータ、上面の型式印字。タイマ H3Y-4: 黒い筐体、上面のダイヤルと目盛（既存）に POWER/UP の2灯（既存）、側面の通気スリット（既存）。
- ソケット PYF14A: 既存の段付き形状に、ネジ座の立体感とホルダ（レバー）の形を整える。

**配線**
- 幹線がブレーカ・電源スイッチの前面に重なって見える（F4）: 机上へ出る幹線を `ch-top` のレーンから直接右へ出すのではなく、**ブレーカの右端より手前（x ≥ 322）で上縁に上がる**経路にする（`desk-exit-ch-top` の `at` をブレーカ・スイッチの投影の下 y=44 に置き、ブレーカ・スイッチの占有矩形を机上経路の障害物にも足す）。正面・盤＋PLC・俯瞰の3視点で幹線の投影がブレーカ・スイッチの前面矩形と交わらないことを射影で検査する。
- 重なり・食い込み・端子からの離れ: 既存の `wire-clearance` 検査（918ケース＋自由配線）を維持し、さらに (a) 全電線の両端が圧着端子のバレル出口から始まる（端子ネジ中心との距離が `WIRE_LUG_REACH_MM ± 0.1mm`）、(b) 電線の管どうしの最小距離 ≥ 直径、(c) 管がソケット・端子台・ブレーカ・スイッチ・電源の立体（占有矩形×高さ）を通らない、を**全内蔵課題の模範配線＋実験の配線済み盤（4メーカー）**で検査する。

### 3.6 PLCの仕様（R4）

**タイマの時間単位は命令で選ぶ（4社共通の仕組み）**
- ラダーIRのタイマセルに `base?: 100 | 10 | 1`（1カウントのms。省略時 100）を足す。ランタイムは `presetMs` をそのまま使うので動作は変わらない。
- 方言ごとの命令名と対応する単位:

| メーカー | 100ms | 10ms | 1ms | 設定値の書き方 |
|---|---|---|---|---|
| 三菱 FX5U | `OUT T` | `OUTH T` | `OUTHS T` | `K<カウント>`（K1〜K32767） |
| オムロン CP1E | `TIM` | `TIMH` | `TMHH` | `#<BCD 4桁>`（#0001〜#9999） |
| ジェイテクト PC10G | `TMR` | `TMRH` | （なし） | `H<16進4桁>`（前提のまま） |
| シャープ JW300 | `TMR` | （なし） | （なし） | 10進4桁（既存） |

- 三菱の番号帯による単位（`timerBaseMs()` の T200/T256 の分岐）は廃止する。旧作業ファイル・旧課題JSONで三菱の T200 以降に `base` が無いときは、**読み込み時に** T200〜255 → 10、T256〜 → 1 を補って以前と同じ動作にする（互換）。
- 「デバイスの入力」窓のタイマ入力に「時間単位」の選択を足し、その機種の命令名と単位を並べる（例「OUT T（0.1秒）」「OUTH T（0.01秒）」「OUTHS T（0.001秒）」）。刻みに合わない設定値の丸めの問いは、選んだ単位で判定する。
- 命令語リストの書き出しは `OUTH T0 K50` のように単位つきの命令名を出す。表記切替で切替先に無い単位（例: シャープへ 10ms）は「切替後の表記で表せない項目」に出し、切替後は 100ms に丸めた上で警告する。
- 課題JSONの `referenceLadder` のタイマセルにも `base` を書ける（省略可）。スキーマ・GUIの課題作成（模範ラダー編集）も対応する。

**三菱 FX5U**
- デバイス範囲を仕様表に合わせる: X0〜X1777 / Y0〜Y1777（8進 1024点）、M0〜M32767、T0〜T1023、C0〜C1023。
- `Shift+F7` / `Shift+F8` の注記を「GX Works3 の割当（2次資料で確認）」に改め、出典表に S9（解説記事2件）を足す。`Alt+F7` / `Alt+F8`（OR 立上り／立下り）は本アプリに OR の微分接点が無いので載せない。
- 3Dの本体: 筐体を明灰（マンセル 0.6B 7.6/0.2 ≈ `#BFC4C6`）、中央の前面パネルを黒、端子台を黒、端子カバーを明灰の半透明にする。LED（PWR/ERR/P.RUN/BAT/CARD、入力16・出力16）の配置と RUN/STOP/RESET スイッチ・Ethernet・SDスロットは既存の矩形のまま、色だけ合わせる。

**オムロン CP1E-N30DR-A**
- 本体表示LEDを POWER（緑）/ RUN（緑）/ ERR/ALM（赤）/ INH（黄）/ PRPHL（黄）/ BKUP（黄）の6灯にする（W479 §3-1-1 の表）。RUN は運転中、ERR/ALM は変換失敗、PRPHL は（周辺USB通信なので）消灯、INH/BKUP は消灯。
- 端子配列を W479 §3-1-3 の図どおりにする（AC電源・30点）:
  - 入力側 上段: `L1` `L2/N` `COM` `0.01` `0.03` `0.05` `0.07` `0.09` `0.11` `1.01` `1.03` `1.05`、下段（半ピッチずれ）: `—` `0.00` `0.02` `0.04` `0.06` `0.08` `0.10` `1.00` `1.02` `1.04` `NC`
  - 出力側 上段: `+` `100.00` `100.01` `100.02` `100.04` `100.05` `100.07` `101.00` `101.02`、下段: `−` `COM` `COM` `COM` `100.03` `COM` `100.06` `COM` `101.01` `101.03`
  - 出力COMの受け持ち（配列から読み取り。COMの直後の点がその群）: COM0={100.00}、COM1={100.01}、COM2={100.02, 100.03, 100.04}、COM3={100.05, 100.06, 100.07}、COM4={101.00〜101.03}。`CP1E_COMMON_SIZES` を `[1, 1, 3, 3, 4]` にする。d-001 の模範配線は COM0→COM1→COM2 を渡り配線する形になる。
- 入出力表示LEDに `IN 00〜11 / 00〜05`、`OUT 00〜07 / 00〜03` の印字を付ける。本体色は明灰のまま、端子台は黒。
- タイマ `TIMH`（10ms）/ `TMHH`（1ms）を足す（上の表）。

### 3.7 動画（R5・R7）

- 9本すべてを、3D・UI・PLCの変更後に `record-tutorials.mjs` で撮り直す。各本に次の「失敗 → 観察 → 考え方 → 修正」を入れ、吹き出しで理由を説明する:

| 本 | 入れる失敗と修正 |
|---|---|
| assembly（B-001） | 線の不足で不合格→修正（既存）に加え、黒PBの**b接点**に配線してしまい、押してもランプが点かない→端子台の a/b/c の読み方を確かめて a接点へつなぎ直す |
| parts（C1-001） | 早すぎる「正常」の訂正（既存） |
| repair（C2-001） | 正常な青線を「断線」と指摘してしまう→測定（DCV）で電圧が来ていることを確かめ、指摘を取り消して本当の断線へ移す |
| plc（三菱） | X9（8進の誤り）の訂正（既存）＋変換せずにモニタを押して「先に変換（F4）してください」が出る→変換してから書込み |
| plc-jtekt | プログラム番号を付けずに `X000` と打って拒まれる→`1X000` に直す |
| plc-omron | `0.12`（この機種に無いビット）を打って拒まれる→`1.00` に直す。出力COMをつなぎ忘れてランプが点かない→I/O割付の表でCOMの受け持ちを読んでつなぐ |

| lab-assemble | 正解のランプを「停止後も点いたまま」に描いてしまい判定で違いが出る→「正解と見くらべる」で時刻を読み、正解を描き直す |
| lab-plc | 停止のb接点を入れ忘れたラダーで動かし、黄を押しても止まらない→ラダーに X1 の b接点を足して動かし直す |

## 4. 互換性

- 作業ファイル: タイマセルの `base` が無ければ 100ms。三菱の T200 以降だけ以前の番号帯の単位を補う（§3.6）。CP1E の端子名は変わらない（並びとCOMの受け持ちが変わる）ので、旧作業ファイルの机上配線はそのまま読める。配線済みの盤（PLC実験）は新しいCOMの受け持ちで作り直す。
- 課題JSON: `referenceLadder` の `base` は省略可。内蔵課題の模範配線（`plcWiringPlan`）はCOMの受け持ちに従って変わるので、全PLC課題の自己判定を再実行する。
- 判定: 合否の基準は変えない。
