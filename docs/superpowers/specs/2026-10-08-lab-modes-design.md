# 新モード「回路実験」「PLC実験」設計（v1.10.0）

- 日付: 2026-10-08
- 起点: v1.9.3（`7e50fa1`）
- 依頼（利用者・原文の要旨）: 「現在4つのモードがあるが更に2つのモードを追加したい。ハード配線を自分で組んでタイムチャートのボタンの入力を指定するとランプ出力がタイムチャート上でどのようになるか見れるようにしたり、自身でタイムチャートを作成しておいて、そこからハード配線をして課題として合格するかという自分で問題を作成できもするモードを、通常の盤上の配線のみのモードとPLCも使ったモードの2つ（PLCのモードはPLCでの回路作成を優先するため、ハード配線はできたものを用意することもできるようにしたい）。リリースまでしておいて」

## 1. 利用者の決定（2026-10-08）

| # | 問い | 回答 |
|---|---|---|
| D1 | 自作したタイムチャート課題の扱い | **その場でだけ使う**（課題ファイルとしては保存しない。作業の一時保存・作業ファイルには残る） |
| D2 | 正解（期待出力）の作り方 | **手で描く＋実験結果から取り込む** |
| D3 | PLCモードの「ハード配線済み」 | **開始時と課題ごとに選べる** |
| D4 | 動画 | **作る**（各モード1本、説明書・ヘルプも更新） |
| D5 | 設計 | モード名「回路実験」「PLC実験」、方式A（既存画面の流用）、版 v1.10.0 で承認 |

## 2. 要件

| # | 要件 |
|---|---|
| R1 | ホームのモードを6つにする（回路組立・部品点検・回路点検・修復・PLC・**回路実験**・**PLC実験**） |
| R2 | 回路実験: 回路組立と同じ盤・部品・配線で自由に回路を組める（模範回路・回路図ヒントは無い） |
| R3 | PLC実験: PLCと同じラダー編集・変換・RUN・モニタ。盤とPLCの配線は「配線済み（固定電線）」か「自分で配線」を開始時に選び、途中でも選び直せる |
| R4 | 押ボタンの押し方（入力）をタイムチャートに描き、「動かす」でランプの実際の動きをタイムチャートで見られる |
| R5 | 正解のランプの動き（期待出力）を描ける。動かした結果を正解へ取り込める |
| R6 | 正解があるとき「判定」で合否を出す（タイムチャートの一致＋基本の配線規則）。結果画面は既存の見比べ・見直しを使える |
| R7 | 作業は自動保存され「続きから」で再開できる。作業ファイルにも保存できる |
| R8 | 例題（内蔵課題のタイムチャート）から始められる |
| R9 | 説明書・ヘルプ・解答操作動画（2本）を追加・更新する |
| R10 | v1.10.0 として既存の手順（CONTRIBUTING §9）でリリースする |

## 3. 方式

既存の「回路組立」「PLC」の画面（`Session` / `PlcSession`）を土台に、実験用の分岐と「タイムチャート実験」の欄を足す（方式A）。配線・3D図・ラダー編集の改善がそのまま新モードにも効き、画面を丸ごと新設するより重複と不具合の元が少ない。

課題データに実験用の2種類（`assemble-lab` / `plc-lab`）を足し、判定の正解の源を「模範回路」ではなく「描いたタイムチャート」にする。比較処理（`compareLogs`）・静的チェック・結果画面・見直しは既存のものを流用する。

## 4. データ

### 4.1 実験のタイムチャート（`LabChart`）

```ts
{
  durationMs: number;          // 2,000〜60,000ms、100ms単位（既定 10,000）
  operations: Operation[];     // 押ボタン PB1〜PB4 の押す・離す（既存の操作列と同じ形）
  expected?: { signal: 'PL1'|'PL2'|'PL3'|'PL4'; on: [fromMs, toMs][] }[]; // 正解の点灯区間（無ければ実験だけ）
  judge: { compareSignals?; tolerance; staticChecks }; // 判定に使うランプ（既定は4つすべて）と許容差（既定は既存と同じ 200ms / 10%）
}
```

- 入力は既存の操作列のまま持ち、編集窓では押ボタンごとの「押している区間」に直して見せる（往復の変換関数を用意する）。終端まで押し続ける区間は `release` を書かない。
- 正解の区間は `0 ≤ from < to ≤ durationMs`、10ms の倍数、重ならず昇順。描く操作は 100ms に吸着する（取り込みは 10ms のまま）。
- 描いていないランプは「ずっと消灯」が正解。判定から外したいランプは `judge.compareSignals` から外す（編集窓の「判定に使う」の印）。

### 4.2 実験の課題（その場で作る課題。保存はしない）

- `assemble-lab`: 共通ヘッダ（`id`=`lab-assemble`、`title`=「回路実験」ほか）＋標準盤（S1〜S4=CR1〜CR4、S5・S6=T1・T2、S7・S8=予備）＋在庫（リレー4・タイマ2）＋ `chart`。
- `plc-lab`: 共通ヘッダ＋ `plc`（メーカー・機種。既定は設定の既定メーカー）＋ `io`（PB1〜PB4→入力0〜3、出力0〜3→CR1〜CR4→PL1〜PL4）＋ `prewired`（真偽）＋ `chart`。
- 判定の静的チェック（既定）
  - 回路実験: 1端子の本数・コイル極性・電源手順・禁則回路。線色・未使用部品は見ない。
  - PLC実験: 上記＋PLC電源の独立。自分で配線するときは二段構成も見る。I/O割付は見ない（自由に割り付けてよい）。
- 自動保存・作業ファイルは既存の `problemSnapshot` に実験の課題をそのまま入れて復元する。課題一覧（`ListMode`）には出さない。

### 4.3 例題

内蔵課題の模範回路／模範ラダーを、その課題の操作列で動かして正解を作る（その場で計算）。

- 回路実験: 自己保持（b-001）・インターロック（b-002）・オンディレー（b-003）・ワンショット（b-005）
- PLC実験: 同じ題材の d 課題（自己保持 d-001・インターロック d-002・オンディレー d-003 ほか）

どの例題も、元の課題の模範で「判定」が合格することを単体テストで確かめる。

## 5. 判定（`judgeAssembleLab` / `judgePlcLab`）

1. 訓練者の盤（PLC実験はラダーとPLCも）を、入力の区間から作った操作列で `durationMs` まで動かす。
2. 実際のチャートを作る（入力4行＋ランプ4行。タイマの目盛付き）。
3. 正解があれば、正解の区間から信号ログを作り、`compareLogs(正解, 実際, judged, tolerance)` で比べる。
4. 静的チェック（§4.2）。
5. 合格 = 正解がある ∧ 不一致0件 ∧ 有効な静的チェックがすべて合格。正解が無いときは「動かす」だけで合否は出さない。
6. PLC実験でラダーが変換できないときは、ラダーの指摘を返して動かさない。

## 6. 画面

### 6.1 ホームと開始

- モードのカードを6枚にする。押すと開始の窓を出す。
  - 回路実験: 「空のタイムチャートで始める」／「例題から始める」（一覧から選ぶ）。
  - PLC実験: 上記＋「盤とPLCの配線」＝「配線済みで始める（ラダー作成に集中）」（既定）／「自分で配線する」。メーカーは既定メーカー（画面内の「メーカーを切り替える」で変えられる）。
- 作業中の実験があるときは既存の「別の課題へ移りますか？」の確認を通す。

### 6.2 練習画面

- 回路実験: 回路組立の画面から、回路図ヒント・回路図エディタ・模範に関わる部分を除く。手順の帯は「①入力を描く ②（正解を作る）③配線 ④動かす ⑤判定」。
- PLC実験: PLCの画面から、模範・仕様チャートに関わる部分を実験用に置き換える。配線済みのときはリレー4個と、盤・PLC・壁コンセントの電線が固定電線で入っている。
- どちらも右の欄に「タイムチャート実験」の欄を置く: 小さなチャート（入力・正解・実際の重ね表示）と「大きく開いて編集」「動かす」「判定」「配線をやり直す」。

### 6.3 タイムチャートの編集（大きな窓）

- 上段に押ボタン4行、下段にランプ4行（各行に「判定に使う」の印）。
- 行の上をドラッグすると、その区間を「押す／点灯」に塗る。点灯している所から始めたドラッグは「消す」。0.1秒刻み。
- 行ごとの区間の一覧（開始秒・終了秒）で、数値の追加・修正・削除もできる（キーボードだけで操作できる）。
- 長さ（秒）、「入力を消す」「正解を消す」「例題を読み込む」。
- 「動かす」: 実際のランプの動きを太線で重ね、正解との違いを赤い帯で示す（結果画面の重ね表示と同じ見た目）。
- 「この結果を正解にする」: 実際の動きを正解へ写す（確認付き）。
- 「判定」: 正解があるとき押せる。既存の結果画面へ進む（模範と見くらべる・動きを見直す・書き出し）。
- 「盤で動きを見る」: 動かした結果を3D盤で区間ごとに再生する（既存の「動きを見直す」の仕組み）。

### 6.4 配線をやり直す

チャートは残したまま、盤だけを最初の状態（PLC実験は配線済み／自分で配線のいずれか）へ戻す。PLC実験ではここで配線の方式を選び直せる（課題ごとに選べる。D3）。

## 7. 説明書・ヘルプ・動画

- 新しい章「回路実験・PLC実験」（目的→手順（番号付き・1手1行）→図→うまくいかないとき）。ホームの説明・困ったときは・用語も更新する。
- F1 のヘルプは新しい2画面からこの章の節を開く。網羅表（coverage.json）に新しい操作要素を登録する。
- 図: ホーム（6モード）、開始の窓、実験画面、編集の窓（入力を描いたところ・動かした結果・取り込み）、判定結果、PLC実験（配線済み）。
- 動画2本（回路実験・PLC実験）を実際の操作で収録する。「入力を描く→動かす→正解を作る（取り込み）→配線をやり直す→配線して判定」の流れ。

## 8. 検証

- content: 実験チャートのスキーマ（区間の検証）、区間⇔操作列の変換、正解からの信号ログ、`judgeAssembleLab` / `judgePlcLab`（正しい回路で合格・違う回路で不合格・取り込んだ正解で合格）、配線済みPLC盤（4メーカー）で静的チェックが通ること、例題が元の模範で合格すること。
- desktop: 編集の塗り・消し・吸着・数値編集、ストアの実験操作、作業ファイルの往復、ヘルプの振り分け、網羅表。
- E2E: 回路実験（入力を描く→配線→動かす→取り込み→やり直し→配線→判定合格）、PLC実験（配線済み→ラダー→動かす→判定合格／自分で配線で始めると盤が空）、画面品質の点検に新画面を加える。
- 既存の検査（`pnpm verify`、内蔵課題の検証、E2E 2回連続、配布物検査、配布版の操作検査、CI）をすべて通してから v1.10.0 を公開する。

## 9. やらないこと

- 自作課題のファイル保存・課題一覧への登録（D1）。
- 拡張盤（PB5〜8・PL5〜8）での実験、ブザー、内部リレーやタイマの行の表示（入力は PB1〜4、出力は PL1〜4）。
- 実機PLCとの通信。
