# 新モード「回路実験」「PLC実験」 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. このリポジトリの AGENTS.md はサブエージェントを禁じているので、本計画は executing-plans（同じセッションでの実行）で進める。

**Goal:** ホームに「回路実験」「PLC実験」を足し、押ボタンの押し方をタイムチャートで決めて動かす・正解を描いて（取り込んで）判定する、を盤配線とPLCの両方でできるようにし、v1.10.0 として公開する。

**Architecture:** 課題データに `assemble-lab` / `plc-lab` を足す（入力は既存の操作列、正解はランプごとの点灯区間）。判定は既存の `runOperations` / `runPlcOperations` / `compareLogs` / `runStaticChecks` を流用する `judgeAssembleLab` / `judgePlcLab`。画面は既存の `Session` / `PlcSession` に実験の分岐と「タイムチャート実験」欄・編集窓を足す。ワーカーに `labRun` を足し、見直し（replay）も実験に対応させる。

**Tech Stack:** TypeScript / zod 4 / Vitest / React 19 / zustand / Electron 44 / Playwright（SwiftShader）。

設計: `docs/superpowers/specs/2026-10-08-lab-modes-design.md`

export const LAB_OUTPUTS = ['PL1', 'PL2', 'PL3', 'PL4'] as const;
export type LabInput = (typeof LAB_INPUTS)[number];
export type LabOutput = (typeof LAB_OUTPUTS)[number];
export const LAB_MIN_DURATION_MS = 2_000;
export const LAB_MAX_DURATION_MS = 60_000;
export const LAB_DEFAULT_DURATION_MS = 10_000;
/** 描くときの吸着の刻み（0.1秒）。取り込んだ正解は 10ms のまま。 */

export const LAB_ASSEMBLE_ID = 'lab-assemble';
export const LAB_PLC_ID = 'lab-plc';

const LabTimeSchema = z.int().min(0).refine((v) => v % TICK_MS === 0, { message: `時刻は ${TICK_MS}ms の倍数にします` });
export const LabIntervalSchema = z.tuple([LabTimeSchema, LabTimeSchema]).refine(([a, b]) => a < b, { message: '区間は開始より終了を後にします' });
export const LabExpectedSchema = z.array(z.strictObject({ signal: z.enum(LAB_OUTPUTS), on: z.array(LabIntervalSchema) }));
export const LabDurationSchema = z.int().min(LAB_MIN_DURATION_MS).max(LAB_MAX_DURATION_MS)
  .refine((v) => v % LAB_DRAW_STEP_MS === 0, { message: '長さは0.1秒単位にします' });

export const ASSEMBLE_LAB_STATIC_CHECKS: StaticChecksData = { ...DEFAULT_STATIC_CHECKS, wireColorRule: false, unusedParts: false };
export const PLC_LAB_STATIC_CHECKS: StaticChecksData = { ...PLC_DEFAULT_STATIC_CHECKS, wireColorRule: false, unusedParts: false, ioAssignment: false };

/** 実験のチャートの共通検査（操作は PB1〜PB4・区間内・押す/離すが交互、正解は昇順で重ならない・区間内、判定のランプは PL1〜PL4）。 */
function checkLabChart(p: { operations: Operation[]; durationMs: number; expected?: LabExpected; judge: JudgeSettings }, ctx: z.RefinementCtx): void { /* 各違反を ctx.addIssue で path 付きで出す */ }

export const AssembleLabProblemSchema = z.strictObject({
  ...ProblemHeaderShape,
  mode: z.literal('assemble-lab'),
  operations: OperationListSchema,
  durationMs: LabDurationSchema,
  expected: LabExpectedSchema.optional(),
  judge: judgeSettingsWithDefaults(ASSEMBLE_LAB_STATIC_CHECKS),
}).superRefine(checkLabChart);

export const PlcLabProblemSchema = z.strictObject({
  ...ProblemHeaderShape,
  mode: z.literal('plc-lab'),
  plc: PlcRefSchema,
  io: PlcIoSchema,
  prewired: z.boolean(),
  operations: OperationListSchema,
  durationMs: LabDurationSchema,
  expected: LabExpectedSchema.optional(),
  judge: judgeSettingsWithDefaults(PLC_LAB_STATIC_CHECKS),
}).superRefine((p, ctx) => { checkLabChart(p, ctx); /* io の x / y が機種の点数内（PlcProblemSchema と同じ検査） */ });

export function createAssembleLabProblem(chart: Partial<LabChartFields> = {}): AssembleLabProblem;   // 標準盤 S1〜S4=CR1〜CR4, S5/S6=T1/T2, S7=CHK, 在庫 リレー4・タイマ2

export type LabJudgeOutcome = { ok: true; value: AssembleLabJudgeResult | PlcLabJudgeResult } | { ok: false; errors: ProblemIssue[] };

export function judgeAssembleLab(problem: AssembleLabProblem, board: BoardDefinition, session: BoardSession, options?: JudgeOptions): LabJudgeOutcome;

判定の手順（設計 §5）: 実際を動かす → `defaultChartSignals(LAB_OUTPUTS, 操作の押ボタン)` でチャート（PLCは `plcTimerMarkers`、盤は `timerMarkers`）→ 正解があれば `compareLogs(labExpectedLog(p), 実際, p.judge.compareSignals ?? LAB_OUTPUTS, p.judge.tolerance)` → `runStaticChecks`（PLCは `plc: { unit, io }` を渡す）→ `judged = expected !== undefined`、`passed = judged && 不一致0 && 静的チェック合格`。PLCでラダーが変換できないときは動かさず `ladderErrors` を返す（`judged` は正解の有無、`passed=false`）。
