2026-09-24の利用者指示「レビューに対応し次のバージョンをリリースすること。使いやすさの点で改善の余地があればそれも盛り込んで」に基づく。N01〜N06の対応、実画面の確認、説明書更新、配布EXE、CI、公開までを実施する。サブエージェントは使用しない。

## 1. 作業中の課題を保護する（N01）

- 課題一覧の開始操作を共通の確認処理へ通す。内部の状態構築・作業ファイル復元にはUI確認を混ぜない。
- 同じ課題は「続きから再開」を第一の選択肢にする。最初からやり直す場合は明示して確認する。
- 別課題へ進む際は作業の保存・破棄・取消を選べるようにする。保存取消/失敗/保存中の追加編集で作業を置き換えない。
- ホームと一覧から現在の作業を再開できるようにする。自動保存の古い読み出しで現在の状態を巻き戻さない。
- 4モードの編集、履歴、解答、故障/修復、ラダー、測定記録について保存保護を検査する。

## 2. 作成中の課題を下書きとして保護する（N02）

- 課題作成の状態をコンポーネント外へ移し、画面を移動しても保持する。
- 不完全なJSONも下書きとして自動保存・復元する。配布可能な課題の検証済み保存とは区別する。
- 専用の版付きファイルへ原子的に保存し、サイズ制限、失敗表示、再試行、通常終了時の最新書込待ちを用意する。
- 検証対象のrevisionを記録し、編集前の検証結果や保存応答を新しい下書きへ適用しない。
- 既存の未保存置換確認、下書き破棄、検証中、保存失敗、起動時復元を検査する。

## 3. 課題作成を図から操作できるようにする（N04）

- 回路図と模範ラダーを既存エディタと同じ記号・入力で編集する入口を追加する。
- 課題作成専用の下書き/履歴を使い、練習中のストアやWorkerを変更しない。
- 型・機種能力・模範自己判定は既存の共通検証を使う。詳細JSONは高度な編集用に残す。
- 編集の適用/取消、Undo/Redo、検証指摘を明確に表示する。
- 回路図とPLCで各1課題をGUIから編集・検証・保存・読込し、実画面で解いて合格まで確認する。

## 4. 案内・日本語・保守性（N03・N05・N06）

### データ保護の詳細

- 下書きは `authoring-draft.json` に版付きで保存する。編集中JSONと最後に配布保存したJSONは各5 MB、全体16 MBを上限とする。
- 壊れた既存下書きは一意なファイル名の控えを残してから新規保存を許可する。控えを作れない場合、将来版の場合、容量制限を超える場合は原本を上書きしない。
- 保存は1本の処理へまとめ、保存中に追加編集された場合は続けて最新状態を書き込む。古い検証結果・保存応答を新しい下書きへ適用しない。
- ラダーの入力欄が未確定の間は、検証と編集終了を無効にする。通常終了も中止して確定/取消を案内する。
- 模範編集の「この画面の変更を取り消す…」は、確認後に編集画面を開いた時点の内容へ戻す。途中の回路を保持したまま後日編集を続けられる。

### 追加した使いやすさの改善

1. 一覧で選んだ級・検索語・難しさ・学習テーマをモードごとに保持する。戻ったときに作業中の課題が絞り込みで隠れる操作を実画面検査で確認し、修正した。初心者向けの入口は条件を解除して3級を開く。
2. 詳細を伴わないWorkerエラーが「undefined」と表示され、異常後に判定を押すと待ち続ける状態を全体検査の画面で確認した。原因詳細が無いときの案内、停止後の判定禁止、旧Workerから遅れて届くエラーを無視する処理を追加した。最初のWorker異常そのものの発生原因はこの観測だけでは断定しない。
3. 配布版の終了検査をWindowsのウィンドウ終了要求に変更した。CDPのページ終了とJavaScriptの `window.close()` ではWebContentsが先に破棄され、通常のウィンドウ終了確認を検証できなかった。通常終了とページ破棄は区別して記録する。APIの意味は [BrowserWindow.close](https://www.electronjs.org/docs/latest/api/browser-window#winclose) と [webContents.close](https://www.electronjs.org/docs/latest/api/web-contents#contentscloseopts) を確認した。
4. 説明書後半の課題作成手順にも新しい作図ボタンを反映した。冒頭の機能説明だけを更新して、後半に詳細JSONだけを案内する文章が残らないよう照合した。
